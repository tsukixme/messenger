## Что сделать

1. Прочитай исходную карточку https://github.com/tsukixme/messenger/blob/main/docs/tasks/T24-Gemini-1.md и замечания Codex. Верни полную исправленную памятку, список исправлений, официальные ссылки и дату сверки. Для владельца — одно действие на шаг; начни с проверки сети/SSH работающей Ubuntu, предыдущую установку вынеси в справочный раздел без предложения пройти её заново.
2. Во всех командах используй ключ `C:\Users\user\Documents\Tildes\.local\ssh\id_ed25519_tildes` вне Git. Предусмотри создание каталога и проверку существующего ключа без перезаписи. Передавай только `.pub`. Защиту ключа кодовой фразой и использование ssh-agent представь как варианты для согласования владельцем; не предписывай изменение служб Windows.
3. Перед первым SSH-входом опиши сверку отпечатка серверного ключа через доверенную консоль ВМ. При несовпадении — остановка. Для проектного `known_hosts` используй один путь `C:\Users\user\Documents\Tildes\.local\ssh\known_hosts` во всех подключениях; не отключай проверку подлинности.
4. Исправь контрольный SSH-вход: `-F none`, `BatchMode=yes`, `IdentitiesOnly=yes`, `PreferredAuthentications=publickey`, `StrictHostKeyChecking=yes`, явные `-i` и `UserKnownHostsFile`. Критерий — новый процесс SSH, код выхода 0, отсутствие интерактивных запросов. Различи пароль Ubuntu и кодовую фразу ключа; для зашифрованного ключа опиши предварительную разблокировку по согласованному способу. Сообщение `echo` само по себе не доказывает успех.
5. Используй одни переменные логина, адреса и порта при передаче `.pub` и проверке: bridge — подтверждённый IP и порт 22; NAT — `127.0.0.1` и 2222. Убери незаменённые `<...>` из команд для копирования. NAT предлагай только после подтверждённой проблемы bridge, не по одному признаку Wi-Fi. Уточни проверку DHCP/статического адреса и доступа к DNS/HTTPS; для работающего bridge пункт NAT в чек-листе — «не требуется».
6. Для Docker оставь официальный APT-репозиторий и проверку `sudo docker run hello-world`. Сверь актуальную инструкцию https://docs.docker.com/engine/install/ubuntu/, проверь существующие установки до предложений об изменениях. Не включай `usermod -aG docker` в обязательные шаги: права root через группу объясни как отдельный вариант, требующий согласования владельцем.
7. Убери безусловную гарантию недоступности физических дисков. В справочном разделе перед форматированием требуй сверку подключённого виртуального диска и его размера. Уже установленную ВМ не размечать повторно. Не описывай raw disk passthrough как шаг настройки проекта.
8. Проверь текст и синтаксис команд без исполнения их действий. Если синтаксический инструмент недоступен — запиши ограничение. Верни полный чек-лист S1: шаг / ожидаемый результат / фактический результат / статус. Проверки источников и синтаксиса отдели от проверок ВМ; незапущенное помечай «не проверено».

## Готово, когда

- Все замечания T24 устранены во всей памятке, командах и чек-листе; нет противоречий между bridge и NAT.
- В памятке последовательно указаны пути под Tildes; перед созданием файлов предусмотрена проверка расположения вне Git. Фактическое наличие ключа/known_hosts не утверждается. Описаны проверка сервера и доказуемый вход указанным ключом.
- Настройки безопасности вынесены на согласование; обязательного расширения прав Docker и повторного форматирования нет.
- Есть результаты доступных проверок текста/синтаксиса и ограничения. Готовность SSH/Docker не объявлена без фактического вывода. Ответ пригоден для `docs/reports/T25-Gemini-1.md`.

## Нельзя

- Не проси и не пиши пароли, токены, приватные ключи и коды; секреты обозначай `***`.
- Не трогай ВМ, чужие проекты, локальные файлы проекта или репозитории. Не выполняй команды памятки, сетевой SSH, Docker, VBoxManage, commit/push/merge. Разрешены чтение публичных ссылок и подготовка текста.
- Не создавай аккаунты, не принимай согласия, не подключай платные услуги, не меняй Firewall, Hyper-V, BIOS, службы Windows или настройки безопасности без решения владельца.
- Не выбирай архитектуру и не начинай следующий этап. Эта карточка не передаёт управление ресурсами.
