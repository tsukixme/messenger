# Задача T22 для Claude

## Контекст

Tildes — свой мессенджер, Android/iOS/web, `kz.tildes.chat`, бюджет без платных сервисов.
Приложение: https://github.com/tsukixme/messenger, PR #1 уже слит в main.
Сервер: https://github.com/tsukixme/messenger-server — Synapse/Docker и Python/FastAPI, вход по номеру через WhatsApp.
Владелец устанавливает Ubuntu в VirtualBox; Codex управляет git и интеграцией. Решения по безопасности/архитектуре сначала утверждает владелец.

## Что сделать

1. Прочитай текущие публичные исходники сервера: `auth/app.py`, `auth/requirements.txt`, `docker-compose.yml`, `nginx/default.conf`, `.env.example`, `flutter/phone_login_page.dart`; и приложения: `.tool_versions.yaml`, `lib/config/app_config.dart`, `lib/config/setting_keys.dart`, `lib/pages/sign_in/`, `lib/widgets/matrix.dart`. Укажи просмотренные commit SHA и существующие тесты.
2. Проверь фактический протокол `/auth/start`, `/auth/status/{sid}`, `/auth/webhook`, `/auth/dev/message`, `/auth/health`. Составь таблицу входных/выходных полей, кодов ответа и переходов сессии; не придумывай уже реализованные функции.
3. Проверь безопасность: подпись webhook, проверку принадлежности номера, случайность и срок действия кодов/сессий, повторное использование, ограничения попыток/запросов, режим разработки, обращение к Synapse admin API и выдачу Matrix access token. Для каждого замечания дай файл/строку, сценарий и проверку воспроизведения без реальных секретов или атак на работающий сервер.
4. Подготовь минимальный план надёжного хранения сессий в SQLite и тестов Python. Для решений, меняющих безопасность или архитектуру, опиши варианты, последствия и рекомендацию; окончательный выбор оставь владельцу. Не реализуй и не интегрируй эти изменения до его согласования.
5. Подготовь план экрана входа по номеру для Flutter: где подключить существующий протокол, как обработать ожидание WhatsApp, истечение срока, отсутствие сети, отмену и успешный Matrix login. Сохрани выбранную пользователем платформу и минимальный объём изменений FluffyChat. Объясни, какие интерфейсы нужно согласовать до написания экрана.
6. Дай конкретный список будущих файлов и независимых проверок: pytest со средствами имитации WhatsApp/Synapse, `flutter analyze`, Android debug build и ручные сценарии. Верни отчёт T22; после согласования Codex выпустит отдельную карточку на реализацию. Дизайн и иконки в T22 не менять.

## Готово, когда

- В отчёте перечислены проверенные файлы/SHA, текущий API и существующие тесты; обнаруженные риски имеют проверяемые основания.
- Для SQLite и Flutter описаны точные точки интеграции, варианты спорных решений и проверки; нет молчаливого выбора нового протокола или сервиса.
- Чётко отделены выполненные проверки, проверки по чтению кода и проверки, которые ещё не запускались. Есть список решений для владельца.
- Ответ можно сохранить как `docs/reports/T22-Claude.md` и самостоятельно перепроверить Codex.

## Нельзя

- Не проси, не показывай и не сохраняй пароли, токены, приватные ключи и содержимое `.env`; секреты обозначай `***`.
- Не трогай чужие проекты, общую рабочую папку, ВМ и общие репозитории: GitHub разрешён только для чтения. Не делай commit/push/merge и не развёртывай сервер.
- Не создавай аккаунты, не принимай согласия, не подключай платные услуги. Не делай запросы к реальным пользователям или работающему серверу.
- Не переписывай архитектуру, авторские упоминания или AGPL-3.0. Не считай тест успешным без фактического запуска.
