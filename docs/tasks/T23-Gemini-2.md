# Задача T23 для Gemini 2

## Контекст

Эту задачу владелец передаёт Antigravity 2.0 (роль Gemini 2, отдельный аккаунт от Antigravity IDE).
Tildes — собственный мессенджер без платных сервисов; приложение: https://github.com/tsukixme/messenger.
Сервер: https://github.com/tsukixme/messenger-server — Synapse/Docker, FastAPI, вход по номеру через WhatsApp; публичный доступ планируется через ngrok Free.
Владелец сам устанавливает Ubuntu и оформляет аккаунты/согласия; Codex управляет git и интеграцией. Сервер ещё не проверен; работающие домен, APK и iOS-путь для тестов не утверждены.

## Что сделать

1. Прочитай публичные README сервера, `.env.example`, `auth/app.py` и `nginx/default.conf` только для понимания требуемых настроек. В начале отчёта укажи дату и просмотренный commit SHA.
2. По актуальной официальной документации подготовь инструкцию для владельца по ngrok Free: аккаунт, доступный статический домен, где владелец лично получает/вводит auth token. Укажи ссылки, ограничения и отдельный способ проверки домена; в ответ проси сообщать только публичный домен, никаких токенов.
3. Подготовь инструкцию для Meta for Developers/WhatsApp Cloud API: какие шаги владелец выполняет сам, тестовый номер и разрешённые получатели, поля настройки webhook и где он лично получает нужные значения. Сверь названия с переменными `.env.example`; значения секретов не копируй.
4. Отдельно проверь по официальным источникам, что доступно без оплаты для тестирования и что может потребовать оплаты/подтверждения бизнеса при реальных пользователях. Не обещай бесплатный промышленный WhatsApp-вход без оснований. Платный или неподтверждённый шаг отметь как препятствие для решения владельцем.
5. Подготовь чек-листы Android и iPhone с колонками «шаг», «ожидаемый результат», «фактический результат», «доказательство», «статус». Покрой открытие по мобильному интернету, ngrok-предупреждение, `/auth/health`, `/_matrix/client/versions`, вход/тайм-аут/неверный код, повторный вход, отправку/получение сообщений, перезапуск и отсутствие сети. Для iPhone раздели Safari/web и приложение: путь установки приложения ещё выбирает владелец.
6. Пока домен/сборки не переданы, оставь фактические тесты со статусом «не проверено». Подготовь черновики описания Tildes и политики конфиденциальности на основе прочитанных потоков данных. Не утверждай непроверенную защиту, сроки хранения, полное соответствие законам или отсутствие передачи данных Meta/ngrok.
7. Верни отчёт T23 с инструкциями и полными чек-листами. Приводи владельцу по одному простому действию за шаг. Все файлы/тексты передавай владельцу в ответе; общие репозитории не редактируй.

## Готово, когда

- Инструкции содержат актуальные официальные ссылки, дату проверки, точные названия полей и места личного ввода владельцем; секретов нет.
- Бесплатные тестовые возможности отделены от возможных платных/неподтверждённых сценариев для реальных пользователей.
- Чек-листы полностью подготовлены; незапущенные тесты честно отмечены «не проверено», есть поля для фактических результатов и доказательств.
- Черновики текстов обозначены как черновики, спорные утверждения вынесены на уточнение. Ответ можно сохранить как `docs/reports/T23-Gemini-2.md`.

## Нельзя

- Не проси и не пиши пароли, токены, App Secret, коды входа и приватные ключи; в примерах используй `***`.
- Не трогай чужие проекты, ВМ, общую папку проекта и репозитории: GitHub только для чтения; не делай commit/push/merge.
- Не создавай аккаунты, не входи от имени владельца, не принимай условия/согласия, не оплачивай и не подключай услуги. Не запрашивай реальные номера телефонов для отчёта.
- Не выбирай архитектуру или путь iOS, не запускай тесты на чужих устройствах и не ставь «пройдено» по одному описанию проверки.

## Формат ответа

Ответ дай одним блоком Markdown с инструкциями, чек-листами и ссылками. Фактические проверки отдели от подготовленных инструкций; секреты — `***`.

```markdown
## Сделано
## Вывод проверки
## Проблемы
## Что дальше
```
