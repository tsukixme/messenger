# Задача T24 для Gemini 1

## Контекст

Эту задачу владелец передаёт Antigravity IDE (отдельный аккаунт, роль Gemini 1).
Tildes: приложение https://github.com/tsukixme/messenger, сервер https://github.com/tsukixme/messenger-server.
На Windows запущена VirtualBox ВМ `Ubuntu-Server-24.04`; владелец сам проходит установку Ubuntu Server 24.04. Последний экран — выбор типа установки, выбран обычный Ubuntu Server.
Нужно подготовить и проверить текст инструкции; управление ВМ не передано. Готовность S1: новое SSH-подключение без пароля и успешный `docker run hello-world`.

## Что сделать

1. По официальным инструкциям Ubuntu, VirtualBox, Microsoft OpenSSH и Docker проверь последовательность дальнейшей установки: обычный Ubuntu Server, сеть, proxy, mirror, диск ВМ, профиль пользователя, OpenSSH, завершение и перезагрузка. Дай ссылки и дату проверки. Инструкция должна соответствовать Ubuntu Server 24.04.
2. Подготовь русскую памятку для нетехнического владельца: одно действие на шаг, точные названия английских полей/кнопок. Пароль владелец придумывает и вводит сам; сторонние проекты/диски хоста инструкция не затрагивает.
3. Подготовь отдельный раздел проверки сети: как владелец смотрит IP внутри Ubuntu, чем подтверждается проблема bridge, как по ранее одобренной инструкции перейти на NAT и добавить SSH forwarding `ssh,tcp,127.0.0.1,2222,,22`. Объясни, какие настройки меняются в ВМ, а какие не должны меняться в Windows. Никаких действий не выполняй.
4. Подготовь команды SSH-ключевого доступа с Windows, учитывая, что `ssh-copy-id` может отсутствовать. Приватный ключ должен остаться в локальной папке проекта за пределами Git; на сервер передаётся только публичный ключ. Личный пароль владелец вводит в локальном терминале. Предложенные настройки безопасности обозначь для согласования, не меняй их сам.
5. Подготовь команды установки Docker в Ubuntu 24.04 по официальной документации и контрольные команды нового SSH-подключения и `docker run hello-world`. Отличай предлагаемые команды от фактически запущенных; не утверждай успех Docker/SSH без вывода.
6. Верни памятку и полный чек-лист S1 с полями «шаг», «ожидаемый результат», «фактический результат», «статус». Пока ничего на ВМ не выполнялось, статус — «не проверено». Отдельно перечисли места, где нужен ручной ввод владельца или его решение. Codex сверит инструкцию до передачи команд владельцу.

## Готово, когда

- Есть самодостаточная инструкция от текущего экрана до критериев S1, с точными действиями и официальными ссылками.
- Проверено, что команды подходят Windows/OpenSSH и Ubuntu Server 24.04; учтено отсутствие `ssh-copy-id` на Windows и недопустимость передачи приватного ключа.
- Памятка не затрагивает диски и настройки безопасности хоста; ручные/спорные шаги явно отмечены.
- Выполненные проверки источников отделены от незапущенных проверок ВМ. Ответ можно сохранить как `docs/reports/T24-Gemini-1.md`.

## Нельзя

- Не проси и не пиши пароли, токены, приватные ключи и коды доступа; секреты — `***`.
- Не трогай чужие проекты, ВМ, общую папку и репозитории. Не отправляй управляющий ввод в VirtualBox, не запускай SSH/Docker/VBoxManage и не делай commit/push/merge.
- Не создавай аккаунты, не принимай согласия, не подключай платные услуги и не меняй Windows Firewall, Hyper-V, BIOS или параметры безопасности.
- Не объявляй этап готовым по подготовленной инструкции. Не выбирай новую архитектуру и не начинай развёртывание сервера.
