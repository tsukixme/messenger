# Задача T28 для Claude

## Контекст

Tildes — пилот мессенджера на Flutter/FluffyChat, AGPL-3.0; сервер Matrix/Synapse уже развёрнут.
Репозитории: https://github.com/tsukixme/messenger и https://github.com/tsukixme/messenger-server.
Codex управляет общими репозиториями и ВМ. Владелец создал admin и demo1–demo4; публичный login и обмен demo1 → demo2 проверены через Matrix API.
Нужен твой отдельный ревью кода и рекомендация по продолжению S4. WhatsApp и S5 отложены владельцем; подпись iOS не выбираем.

## Что сделать

1. Прочитай серверный отчёт https://github.com/tsukixme/messenger-server/blob/main/docs/reports/S3-codex.md и проверь PR со скриптами пользователей/копий: https://github.com/tsukixme/messenger-server/pull/2. Проверь скрытый ввод, stdin вместо argv, неадминскую регистрацию, консистентность копий, исключение .env, права 700/600 и хранение пяти архивов.
2. Проверь S4 приложения: https://github.com/tsukixme/messenger/pull/2, включая docs/reports/S4-codex.md. Домен меняется в одном AppConfig.defaultHomeserver; workflow — из твоего набора, с явно описанной установкой nightly/rust-src/WASM для web. Analyze до/после чистый; сборки и телефонные тесты пока не подтверждены.
3. Проверь отдельный серверный патч S4: https://github.com/tsukixme/messenger-server/pull/3. Это твой nginx-web.patch.md: статические файлы, SPA fallback, read-only том и ignore; API блоки сохранены. nginx -t и Compose config прошли, runtime web ещё не опубликован.
4. Дай отдельный вердикт по каждому из трёх PR: «одобрен» или точные замечания с файлом/строкой. Не называй незапущенные сборки успешными. Если нужен патч, передай его текстом владельцу; общий репозиторий не редактируй.
5. Предложи владельцу путь проверки нового workflow: A — merge после твоего ревью и явного подтверждения владельца, затем workflow_dispatch; B — отдельно согласованный ограниченный PR/веточный trigger до merge. GitHub требует workflow_dispatch в default branch. Сам trigger или архитектуру не меняй.
6. Разбери Windows-ошибки из полного отчёта S4: две попытки prepare-web (DNS, затем FRB FormatException при where.exe wasm-pack) и остановка native tests в webcrypto/CMake Ninja с platform x64. Предложи проверяемые следующие команды/варианты без переписывания приложения и без обещания успеха. Повтор операции после двух неудач отдельно разрешает владелец.
7. Проверь доступные результаты существующего Pull Request Workflow: https://github.com/tsukixme/messenger/actions/runs/36966790611. Он остановился на Check licenses, зависимые сборки пропущены; подробные логи API недоступны Codex (HTTP 401), точная причина не установлена. Matrix Notification https://github.com/tsukixme/messenger/actions/runs/36966790805 также упал. Эти workflows Codex не менял; рекомендации по их исправлению передай отдельно, не приписывая им успешную сборку Tildes.

## Готово, когда

- Для каждого PR дан отдельный аргументированный вердикт; замечания привязаны к текущему diff.
- Объяснены варианты первого запуска CI и дальнейшей проверки web, с указанием необходимых решений владельца.
- Проверенные результаты отделены от предположений и будущих тестов; ограничения доступа названы явно.

## Нельзя

- Не проси и не пиши пароли, токены, Meta secret или содержимое баз; секреты заменяй на ***.
- Не трогай ВМ, общие репозитории, чужие проекты; не сливай PR, не оформляй аккаунты/согласия и платные услуги.
- Не реализуй S5, WhatsApp, новые способы подписи iOS или отложенный S3 шаг 8.

## Формат ответа

Один блок Markdown для сохранения в docs/reports/T28-Claude.md:

```markdown
## Сделано
## Вывод проверки
## Проблемы
## Что дальше
```

В «Вывод проверки» укажи три вердикта и фактически доступные источники/проверки; незапущенные команды обозначь прямо. Codex самостоятельно перепроверит результат до интеграции.
