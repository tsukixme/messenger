## Вывод проверки

- [ngrok Free Plan Limits](https://ngrok.com/docs/pricing-limits/free-plan-limits)
  указывает до 3 online endpoints, 3 concurrent agents, один назначенный
  dev domain, 1 ГБ исходящего трафика и 20 000 HTTP-запросов в месяц.
  Предупреждение относится к HTML browser traffic; cookie после Visit
  скрывает его на 7 дней. Подтверждён заголовок обхода с любым значением;
  вариант User-Agent требует non-standard значения.
- [Официальная страница цен WhatsApp](https://whatsappbusiness.com/products/platform-pricing/)
  описывает оплату за доставленные сообщения и бесплатные service-ответы
  в 24-часовом окне. Страница подробных обновлений
  [Meta pricing](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing#updates-to-rate-cards)
  не открылась: 429 Too Many Requests. Точные действующие квоты/изменения
  на дату проверки не подтверждены. Ни «1000 бесплатных conversations»,
  ни гарантированная бесплатность промышленного входа не установлены.
- [Meta Newsroom, 18.09.2025](https://about.fb.com/news/2025/09/bringing-new-tools-to-help-businesses-boost-engagement-customer-support-and-discoverability/)
  описывает совместное использование WhatsApp Business App и Platform
  на одном номере. Материал относится к Индии и не подтверждает доступность
  этого способа для владельца в Казахстане, но опровергает абсолютное
  утверждение «номер навсегда только в API».
- [Apple Developer Program](https://developer.apple.com/programs/)
  относит TestFlight к членству в программе со стандартной стоимостью
  $99/год. Бесплатный аккаунт допускает тестирование собственных устройств
  через Xcode. Путь iOS для Tildes не выбран.
- Переменные `.env.example` сопоставлены корректно. `curl -I` проверяет
  заголовки, поэтому не может подтвердить тело `pilot ok`. `/auth/status`
  возвращает логин/пароль, Matrix-токен получает клиент отдельным входом.
  На устройствах и реальном домене запросы не выполнялись; статусы
  «не проверено» в отчёте обоснованы.

## Проблемы

1. Лимит «один агент/туннель» и постоянное предупреждение ngrok неверны.
   Выдача назначенного dev domain смешана с резервированием собственного
   имени. Нужно уточнить шаги кабинета по доступному подтверждённому интерфейсу.
2. Нет конкретных доступных источников для объявленных обязательных
   юрлица, business verification, корпоративного домена и банковской карты
   для любой аудитории. Ограничение пяти получателей и запрет иных входящих
   из-за Development Mode также не подтверждены в этой проверке.
   Такие выводы нужно пометить неизвестными, не объявлять установленными
   препятствиями; проверки условий аккаунта выполняет владелец лично.
3. Устаревшая/неподтверждённая модель оплаты conversations представлена
   как действующая. Необходимо сверить дату вступления условий и категорию
   конкретного сообщения; доступ к rate cards пока ограничен.
4. TestFlight ошибочно предложен как путь без оплаченного членства.
   Смешаны Ad Hoc и Enterprise; выбор iOS остаётся у владельца.
5. Чек-листы Safari/iOS неполны: отсутствуют отдельные проверки неверного
   кода/чужого номера, TTL, повторного входа, обмена сообщениями,
   перезапусков и отсутствия сети. В Android неверно назван Matrix-токен
   на выходе auth; версии Matrix должны оцениваться по фактическому JSON.
6. Доказательства не должны содержать коды входа, номера, sid, пароли и
   access tokens: строки с логами/скриншотами нужно снабдить правилом маскировки.
   Готовую строку Verify Token из примера нельзя предлагать для копирования:
   нужен локально выбранный случайный секрет, в ответе — только `***`.
   Черновик политики требует уточнить lazy-очистку памяти, хранение попыток,
   логи и наличие телефона в Matrix ID/профиле; сроки удаления не утверждены.
7. Вывод «архитектура готова к первичному запуску» не является результатом
   испытаний и не учитывает [подтверждённый риск auth](T22-codex-review.md).
   Владелец позднее подтвердил запуск Ubuntu, но SSH не проверен,
   Docker ещё не установлен: S1 не принят. `docker compose up -d`
   и следующий этап не разрешены этой карточкой. Подготовка кодового PR
   auth отдельно разрешена новым поручением об auth-update.zip.
