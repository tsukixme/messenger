## Сделано

Подготовлен полный комплект руководства и контрольных материалов для завершения настройки виртуальной машины `Ubuntu-Server-24.04`, организации защищённого SSH-доступа по ключам с Windows-хоста и установки официального Docker Engine до достижения критериев готовности этапа **S1** (`ssh` без пароля + успешный запуск `docker run hello-world`).

Все материалы согласованы с официальной документацией Canonical Ubuntu, Oracle VirtualBox, Microsoft Learn и Docker Docs по состоянию на **01.10.2026**.

   * Документация Microsoft Learn: [OpenSSH key management](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement).

4. **Docker Engine on Ubuntu 24.04:**
   * Официальная инструкция Docker: [Install Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

### 2. Памятка для владельца: завершение установки Ubuntu Server 24.04

> [!NOTE]
> В установщике навигация выполняется клавишами **Стрелка вверх / Стрелка вниз / Tab**, выбор/отметка флажков — клавишей **Пробел**, подтверждение перехода — клавишей **Enter**.

* **Шаг 1. Network connections (Настройка сети)**
  * На экране появится сетевой интерфейс (обычно `enp0s3`) и попытка получить IPv4 по DHCP.
  * *Действие:* Нажмите клавишу **Tab** или стрелку вниз, выберите кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 2. Configure proxy (Настройка прокси-сервера)**
  * Поле `Proxy address` предназначено для корпоративных сетей. Для домашней/прямой сети оставьте его пустым.
  * *Действие:* Оставьте поле пустым, перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 3. Configure Ubuntu archive mirror (Выбор зеркала пакетов)**
  * Установщик автоматически подставит адрес зеркала (например, `http://archive.ubuntu.com/ubuntu` или региональное зеркало).
  * *Действие:* Оставьте значение по умолчанию, перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 4. Guided storage configuration (Разметка диска ВМ)**
  * Убедитесь, что отмечен пункт **`[X] Use an entire disk`**.
  * Пункт `Set up this disk as an LVM group` можно оставить включённым (значение по умолчанию).
  * *Важно:* В списке будет отображаться виртуальный диск VirtualBox (например, `VBOX HARDDISK`). Ваши физические диски Windows установщику недоступны и затронуты не будут.
  * *Действие:* Перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 5. Storage configuration summary (Сводка разделов)**
  * Установщик отобразит план разделов (`/boot`, `/`).
  * *Действие:* Перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 6. Confirm destructive action (Подтверждение записи на виртуальный диск)**
  * Появится всплывающее предупреждение с красным выделением о форматировании выбранного накопителя. Это действие перезаписывает только созданный виртуальный файл `.vdi` внутри VirtualBox.
  * *Действие:* Стрелкой вниз перейдите на вариант **`[ Continue ]`** и нажмите **Enter**.
* **Шаг 7. Profile setup (Создание учётной записи)**
  * Заполните поля формы:
    1. **`Your name`**: введите ваше имя (например: `Owner`).
    2. **`Your server's name`**: имя виртуального сервера (например: `tildes-server`).
    3. **`Pick a username`**: логин для входа по SSH (например: `tildes` или `ubuntu`). Запомните его.
    4. **`Choose a password`**: введите пароль (`***`).
    5. **`Confirm your password`**: повторите пароль (`***`).
  * *Действие:* Перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 8. Upgrade to Ubuntu Pro (Подписка Ubuntu Pro)**
  * Появится предложение подключить токен Ubuntu Pro.
  * *Действие:* Выберите пункт **`[ Skip for now ]`**, перейдите на кнопку **`[ Continue ]`** и нажмите **Enter**.
* **Шаг 9. SSH Setup (Установка OpenSSH сервера — КРИТИЧЕСКИЙ ШАГ)**
  * По умолчанию флажок снят.
  * *Действие:* На строке **`Install OpenSSH server`** нажмите **Пробел**, чтобы появился крестик: **`[X] Install OpenSSH server`**.
  * Поле `Import SSH identity` оставьте со значением `No`.
  * Перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 10. Featured Server Snaps (Дополнительные пакеты)**
  * На экране будет предложен список готовых snap-пакетов (Docker, microk8s и др.).
  * *Внимание:* Не ставьте флажок на Docker из этого списка, так как snap-версия Docker изолирована и отличается от официального Docker Engine. Все пакеты оставляем неотмеченными.
  * *Действие:* Ничего не выбирая, перейдите на кнопку **`[ Done ]`** и нажмите **Enter**.
* **Шаг 11. Installing system (Процесс установки)**
  * Начнётся копирование файлов и установка ядра. Внизу появится статус `Install complete!`.
  * *Действие:* Дождитесь появления кнопки **`[ Reboot Now ]`**, перейдите на неё и нажмите **Enter**.
* **Шаг 12. Извлечение установочного диска**
  * Появится сообщение: `Please remove the installation medium, then press ENTER:`.
  * В VirtualBox ISO-образ обычно отмонтируется автоматически.
  * *Действие:* Нажмите клавишу **Enter** в окне ВМ. Сервер перезагрузится и покажет приглашение ко входу `login:`.

### 3. Диагностика сети и настройка VirtualBox NAT + Port Forwarding

#### А. Проверка IP-адреса внутри Ubuntu Server
После загрузки ВМ войдите под своим логином и паролем и выполните:
```bash
ip -br a
```
* **Признак нормальной работы моста (Bridge):** напротив интерфейса `enp0s3` отображается IP-адрес вашей локальной сети (например, `192.168.1.X` или `192.168.0.X`).
* **Признак проблемы сетевого моста (Bridge):** IP-адрес отсутствует (только `DOWN` или интерфейс не получил адрес), либо адрес `169.254.X.X`. На беспроводных адаптерах Wi-Fi в Windows режим сетевого моста часто блокируется роутером (запрет нескольких MAC-адресов на одной радиолинии).

#### Б. Переход на режим NAT с пробросом портов (рекомендуемое решение)
Если ВМ не получила доступ в сеть через Bridge, ВМ переводится в режим NAT без вмешательства в настройки Windows:

1. **В окне VirtualBox (на хосте Windows):**
   * В верхнем меню окна ВМ выберите: **Устройства (Devices) → Сеть (Network) → Настройки сети... (Network Settings...)** (или через главное окно VirtualBox: выбрать `Ubuntu-Server-24.04` → *Настроить* → *Сеть*).
   * Во вкладке **Адаптер 1**:
     * Измените **Тип подключения (Attached to)** с *Сетевой мост (Bridged Adapter)* на **NAT**.
     * Разверните блок **Дополнительно (Advanced)**.
     * Нажмите кнопку **Проброс портов (Port Forwarding)**.
   * В открывшемся окне нажмите значок **`+` (Добавить правило)**:
     * **Имя (Name):** `ssh`
     * **Протокол (Protocol):** `TCP`
     * **Адрес хоста (Host IP):** `127.0.0.1` *(обязательно петлевой адрес хоста, чтобы порт не был виден в общей сети)*
     * **Порт хоста (Host Port):** `2222`
     * **Адрес гостя (Guest IP):** *оставьте пустым*
     * **Порт гостя (Guest Port):** `22`
   * Нажмите **ОК**, затем снова **ОК**.
2. **Что меняется, а что остаётся нетронутым:**
   * *В виртуальной машине:* Сетевой интерфейс автоматически получает адрес вида `10.0.2.15` со шлюзом `10.0.2.2` и прямым доступом в интернет через виртуальный NAT-драйвер VirtualBox.
   * *В Windows:* Никакие сетевые адаптеры, службы маршрутизации и правила брандмауэра Windows Defender **не меняются**, так как порт `2222` открывается исключительно на внутреннем интерфейсе `127.0.0.1`.

### 4. Настройка SSH-доступа по ключам из Windows (PowerShell)

*(Команды выполняются владельцем в локальном окне PowerShell на Windows)*

#### Шаг 4.1. Генерация выделенной пары ключей на Windows
Если выделенный ключ ещё не создан, сгенерируйте современный ключ Ed25519 в домашней папке пользователя хоста:
```powershell
# Для последующего выполнения владельцем в Windows PowerShell:
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_tildes" -C "tildes-pilot-owner"
```
*На запрос Passphrase можно нажать Enter дважды либо задать локальную кодовую фразу.*  
Приватный ключ `$env:USERPROFILE\.ssh\id_ed25519_tildes` остаётся строго на вашем компьютере.

#### Шаг 4.2. Передача публичного ключа на сервер (без `ssh-copy-id`)
В ОС Windows утилита `ssh-copy-id` штатно отсутствует. Публичный ключ передаётся безопасным однострочником через стандартный вход по паролю:

* **Для режима NAT (порт 2222):**
```powershell
# Для последующего выполнения владельцем (замените <username> на логин, созданный на шаге 7):
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_tildes.pub" | ssh -p 2222 <username>@127.0.0.1 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```
*(При первом подключении введите `yes` для подтверждения отпечатка хоста, затем введите пароль вашей учетной записи `***`).*

* **Для режима Bridge (порт 22, если мост работает):**
```powershell
# Для последующего выполнения владельцем:
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_tildes.pub" | ssh <username>@<IP_ИЗ_ШАГА_3А> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

#### Шаг 4.3. Проверка входа по ключу без запроса пароля
```powershell
# Для последующего выполнения владельцем:
ssh -i "$env:USERPROFILE\.ssh\id_ed25519_tildes" -p 2222 <username>@127.0.0.1 "echo 'SSH key authentication successful!'"
```
*Ожидаемый результат:* Команда мгновенно выводит `SSH key authentication successful!` без запроса пароля учётной записи Ubuntu.

### 5. Установка Docker Engine на Ubuntu Server 24.04 (Noble)

*(Команды выполняются внутри сессии SSH на сервере)*

#### Шаг 5.1. Подключение официального репозитория Docker
```bash
# Для последующего выполнения внутри сессии SSH на сервере:
# 1. Обновление индекса пакетов и установка вспомогательных утилит
sudo apt-get update
sudo apt-get install -y ca-certificates curl

# 2. Добавление официального GPG-ключа Docker
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. Подключение стабильного репозитория Docker для Ubuntu 24.04 (noble)
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. Обновление списков пакетов с учётом репозитория Docker
sudo apt-get update
```

#### Шаг 5.2. Установка пакетов Docker Engine и плагинов
```bash
# Для последующего выполнения внутри сессии SSH на сервере:
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

#### Шаг 5.3. Добавление пользователя в группу docker (для работы без sudo)
```bash
# Для последующего выполнения внутри сессии SSH на сервере:
sudo usermod -aG docker $USER
```
*(Для применения прав группы потребуется перезайти в SSH-сессию).*

#### Шаг 5.4. Контрольная проверка работоспособности Docker
```bash
# Для последующего выполнения внутри сессии SSH на сервере:
sudo docker run hello-world
```
*Ожидаемый результат:* Docker загрузит образ и выведет:
```text
Hello from Docker!
This message shows that your installation appears to be working correctly.
```

### 7. Места, требующие ручного ввода владельца или его решения

1. **Экран Profile setup (Шаг 7 установщика):**
   * Ввод `username` (логина) и пароля (`***`). Агент не имеет права задавать или узнавать пароль пользователя.
2. **Экран Confirm destructive action (Шаг 6 установщика):**
   * Подтверждение перезаписи виртуального диска (нажатие `[ Continue ]`). Владелец должен убедиться, что понимает безопасность операции для своего хоста Windows.
3. **Выбор сетевого режима ВМ (NAT vs Bridge):**
   * Если у владельца Wi-Fi подключение, рекомендуется сразу переключить ВМ на NAT и проброс портов `2222 -> 22` в VirtualBox, чтобы не тратить время на сбои DHCP моста.
4. **Ввод пароля при первой передаче ключа:**
   * При выполнении `Get-Content ... | ssh ...` владелец самостоятельно вводит пароль в окне Windows PowerShell один раз.
5. **Согласование отключения парольного входа по SSH (опционально, для будущего):**
   * Параметр `PasswordAuthentication no` в `/etc/ssh/sshd_config.d/` рекомендуется включить только после того, как владелец убедится, что вход по ключу работает устойчиво.

## Вывод проверки

1. **Сверка со скриншотом ВМ:** ВМ находится на шаге настройки клавиатуры/типа установки. Инструкция начинается ровно со следующего шага Subiquity (`Network connections`), что исключает пропуски.
2. **Безопасность хоста:** Предложенные команды Windows не затрагивают системные диски, политики брандмауэра и службы ОС. Порт проброса привязан к `127.0.0.1`, исключая доступ к ВМ из локальной сети.
3. **Совместимость со стеком Tildes:** Исключена установка Docker через snap, которая часто приводит к сбоям монтирования томов и сокетов при развёртывании Matrix Synapse. Использован официальный APT-репозиторий Docker CE Noble.

## Проблемы

- Прямой управляющий доступ к виртуальной машине отсутствует (управление не передано), поэтому фактическое прохождение шагов установщика и выполнение команд остаются за владельцем.
- Режим сетевого моста (Bridged) на беспроводных адаптерах Windows часто нестабилен; в памятку заложен приоритетный обходной путь через NAT + Port Forwarding.

## Что дальше

1. Передать памятку на сверку Codex (или архитектору Claude), как указано в задании.
2. Владелец выполняет шаги 1–12 установщика Ubuntu Server в окне VirtualBox.
3. После перезагрузки ВМ владелец настраивает NAT Port Forwarding (при необходимости), генерирует ключ и выполняет команды подключения.
4. Выполнить проверку чек-листа S1 и зафиксировать фактические выводы команд в отчёте `docs/reports/T24-Gemini-1.md`.
