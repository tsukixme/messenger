## Вывод проверки

Это проверка функций с подменой FastAPI-маршрутизации и всех клиентов HTTP
на объекты в памяти. Использованы настоящие модели Pydantic и фиктивные
настройки. Создание сетевых сокетов запрещено сценарием во время проверки.
Это не ASGI/pytest-прогон, не проверка nginx и не атака на работающий сервер.
Реальных сетевых запросов — 0; коды, номера и созданные пароли не печатались.

| Сценарий | Самостоятельный результат |
|---|---|
| P1: пустой `WA_APP_SECRET`, `DEV_MODE=false`, неподписанный webhook | Сессия подтверждена; возвращены поля `verified`, `user_id`, `password`. Заглушка существующего аккаунта получила GET/PUT смены пароля. Повторное получение — 410. |
| P2: маршрут разработки | При `DEV_MODE=true` подтверждает сессию; при `false` — 404. |
| P3: непустой фиктивный секрет | Отсутствующая/неверная подпись — 403; правильная HMAC — подтверждение. |
| Чужой отправитель и истечение срока | Чужой номер не подтверждён; просроченная сессия — 410. |
| Лимит одного номера | Шестая попытка за час — 429. |
| P4: 20 000 разных номеров | Все приняты за 11,413 с; HTTP-клиент не вызывался. После принудительного истечения и cleanup: sessions=0, starts=20 000. |
| P5: 10 цифр | Подтверждено добавление префикса 7. Контракт допустимых стран ещё не утверждён. |
| P6: заглушка Synapse отвечает 500 | Первый status — 502; повтор с тем же sid — 410. |

## Проблемы

- Обязательная часть Flutter-аудита T22 не завершена: Claude прямо отметил,
  что не прочитал `lib/pages/sign_in/`, `lib/widgets/matrix.dart` и не сверил
  текущую версию Flutter. Утверждение об отсутствии Flutter-тестов неверно.
- В P4 неверно описана рассылка кодов жертвам от `/auth/start`: этот маршрут
  возвращает код/ссылку клиенту. Подтверждён рост структуры попыток и
  отсутствие общего ограничения; порог отказа сервера не измерялся.
- Предложенный тест отсутствующей подписи **при заданном секрете** уже
  проходит на нынешнем коде. Для устранения P1 нужен сценарий пустого
  секрета, различающий старое и утверждённое новое поведение.
- План SQLite не определяет атомарное потребление сессии, конкурентные
  запросы и восстановление после 502. Нужно описать варианты и проверки;
  окончательные решения по безопасности и архитектуре остаются у владельца.
- **Решение владельца получено 2026-10-01:** согласованы отказ запуска
  вне тестового режима при пустом `WA_APP_SECRET` и `DEV_MODE=false`
  по умолчанию. Ответ: «Да, согласовать оба изменения (рекомендую)».
  Подготовка этих исправлений и тестов включена в T26; выбор SQLite,
  нормализация стран, общий лимит и восстановление после 502 ещё не одобрены.
- Позднее владелец передал `auth-update.zip` и прямо разрешил применить
  пакет по `README-for-codex.md`, включая SQLite, IP-лимит и восстановление
  после сбоя Synapse. Это последующее поручение заменяет ограничение
  предыдущего абзаца для содержащегося в архиве кода. Codex проверяет
  пакет и готовит отдельный серверный PR; Flutter из пакета исключён.
